# перенос на другой компьютер

Архив с `.env` и PostgreSQL-дампом содержит секреты и данные проекта. Передавай
его только по закрытому каналу. Для переноса существующих вложений также нужна
согласованная копия закрытого `MEDIA_STORAGE_ROOT` с сохранением относительных
путей и прав доступа.

На новом компьютере запусти пустой Redis для rate limit и уведомлений worker.
Сессии пользователей и состояние очереди медиа хранятся в PostgreSQL и
переносятся с дампом.

## на новом компьютере

1. Для полного проверенного окружения используй Ubuntu 24.04 или WSL с Python
   3.14, PostgreSQL 16 и Redis 7. Для старого архива с дампом выбери версию
   PostgreSQL и `pg_restore`, совместимую с версией создания дампа
2. Распакуй архив и перейди в его папку
3. Проверь `.env`: адреса и пароль относятся к новому компьютеру
4. Создай пустую PostgreSQL-базу с пользователем из `.env`
5. Выполни `sh scripts/setup_portable.sh`
6. Если нужны текущие данные, выполни

   ```bash
   RESTORE_DATABASE=1 sh scripts/restore_portable_database.sh
   ```

   Скрипт очищает указанную базу. Используй только новую пустую базу

7. Примени миграции и запусти приложение. Текущая схема включает миграции
   `001`–`026`, включая `026_realtime_outbox`. Первичную инвентаризацию
   выполняй при остановленной записи по инструкции в [production.md](production.md#дисковая-квота-медиахранилища)

   ```bash
   .venv/bin/python -m scripts.migrate
   .venv/bin/uvicorn app.main:app --reload
   ```

8. Открой `http://127.0.0.1:8000/ready` и убедись, что PostgreSQL и Redis отвечают

9. Для долгоживущей установки добавь в расписание очистку истёкших сессий,
   неиспользованных posting claims и файлов из очереди:

   ```bash
   .venv/bin/python -m scripts.cleanup_sessions
   .venv/bin/python -m scripts.cleanup_posting_claims
   .venv/bin/python -m scripts.cleanup_media_files
   ```

10. Для медиа установи FFmpeg и FFprobe с кодеками для audio, voice, MP4 и WebM,
    `librlottie0-1` для TGS и `util-linux` с `/usr/bin/prlimit`. Укажи абсолютный
    `MEDIA_STORAGE_ROOT` в `.env` и настрой internal locations из
    `deploy/nginx.conf.example` для выдачи `preview`, `display` и `content`.
    Корневой каталог файлов должен оставаться закрытым. Запусти worker с тем же `.env`:

    ```bash
    .venv/bin/python -m scripts.media_worker
    ```

Публичная загрузка по claim принимает JPEG, PNG, статический и анимированный
WebP, GIF, MP3, M4A/AAC, OGG/Opus и MP4/H.264 с необязательным AAC. Готовые
производные выдаются через FastAPI и internal Nginx после проверки видимости.
Обработка `video_note` и ответы со статическим WebP, TGS или WebM доступны во
внутренних сервисах. Telegram, WebSocket и публичный frontend остаются отдельными
этапами. `NoopMediaScanner` пропускает файлы без антивирусной проверки. Интерфейс
`MediaScanner` сохранён, ClamAV, Prometheus и Grafana отложены. Для эксплуатации
обязательны дисковые квоты, надёжная фоновая очистка и базовый мониторинг. При
переносе сохрани изоляцию worker и ограничения ресурсов. После восстановления
тома и сверки его инвентаризации установи таймеры очистки и мониторинга на
постоянном Linux-хосте по [руководству по эксплуатации](production.md#worker-очистка-и-мониторинг).

Подробные требования к серверу, форматам и проверкам есть в
[инструкции по развёртыванию](production.md).
